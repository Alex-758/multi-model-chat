# 09 · 下一版本路线图建议

> 依据：本次审计的未解决问题清单（08 号报告）+ 架构弱点。按「用户价值/风险 ÷ 改动半径」排序，供决策，非承诺。

## v1.4.6（正确性收尾，小步快跑）
1. **B3 记账口径**：partial 快照 + sessionTokens 按 modelId 去重（会话累计不再重复计重试模型）。
2. **C12 在线验证**：确认 Gemini 兼容层流式 usage 后决定是否加白名单。
3. **D9 保存失败兜底**：全局脏标记 + 关窗强提示（磁盘满/EPERM 场景数据不再裸奔）。
4. **测试基建**：test.js 套件间 500ms 间隔，消除 e2e-deep 偶发 mock 不可达。

## v1.5.0（数据与性能主战场）
1. **增量保存（D7/E1）**：渲染层脏会话跟踪 + 主进程会话粒度合并写；14MB 库的 30ms/次 × 每轮 3~8 次降为个位数毫秒。
2. **冷开装饰 idle 化（E2）+ finalize 两阶段（E3）**：大会话冷开 1.3~1.5s → 亚秒；综合完成瞬间不再顿挫。
3. **附件单跳（E5）**：主进程直读直提取，砍掉两跳 base64（20MB 文件省 ~300ms CPU 与 200MB 内存尖峰）。
4. **导出打包图片（D6）**：备份格式 v2（images/ 目录随 zip），导入向后兼容。
5. **输入阈值（E4）**：超长粘贴不再拖垮打字跟手性。

## v1.6.x（体验增强，按需）
1. **finish_reason 提示（C5）**：截断/内容拦截不再是"看起来完整的 ✓"。
2. **原生搜索引用注回（C11）**：annotations 进「📎 搜索来源」。
3. **搜索可中止（B8）+ 多实例提示（D10）+ .bak 时间戳（D8）+ F12 按打包裁剪（A6）**：一批防御纵深小项。
4. **ui-chat.js 拆分**：~2850 行按 轮次渲染/综合/交叉审查/导出 拆模块（本次 8 处修复集中此文件，拆分可缩小回归半径）。

## 长期
- store.json → 分文件/SQLite（会话级读写，启动不再全量 parse）。
- 渲染层状态机显式化（streaming/runToken/pending 的隐式约定改为单一状态源）。
- 引入 ESLint 基线（本次发现的多处 `+` 拼接注入风险可被 lint 规则提前拦截）。
