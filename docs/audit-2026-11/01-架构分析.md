# 01 · 架构分析（v1.4.5 @ audit/quality-20261101）

> 审计基线：master 2503402。本文以当前代码为准（非 README 推测），全部结论经五项审计子代理通读源码 + 历史提交核对。

## 1. 模块依赖图

```
主进程 (src/main)
  main.js ──┬─ providers.js   （HTTP/SSE 调 LLM，openai + anthropic 两种格式）
            ├─ store.js       （store.json 原子写、safeStorage 密钥加密、损坏备份）
            ├─ images.js      （mmimg:// 协议、图片落盘/OCR、文档提取、markitdown 双通道）
            ├─ search.js      （必应/Tavily 联网搜索）
            └─ preload.js     （contextBridge 白名单 API）
渲染层 (src/renderer/js)
  app.js      状态/配置归一（normalizeConfig 4 级 presetVersion 迁移链）/ MM.save / flush 钩子
  ui-chat.js  聊天编排 ~2850 行：轮次/版本池/综合/交叉审查/来源角标/导出
  ui-sessions.js 会话 CRUD/侧栏/token 记账
  ui-settings.js 设置页（服务商/搜索/综合/数据管理）
  merge.js    分句/聚类/IDF 相似度/审查与仲裁提示词/预算裁剪（纯函数）
  markdown.js 自研 Markdown 渲染（转义先行 + 代码块占位符）
  model-info.js / util.js
依赖方向：ui-*.js → app.js(MM.state) + markdown/merge/util；全部经 preload 的 window.api 与主进程通信；
渲染层零直接网络/文件访问（connect-src 'self'）。
```

## 3. 模型请求生命周期

```
渲染层 nextReqId(prefix+seq+随机后缀) ── pending.set(ctx) ── api.send
  → main: activeRequests.set(id, AbortController) → 每 target 一个 job
  → providers.streamChat：buildBody（联网参数/图片部件/token 字段判定）→ fetch SSE
     · 120s 空闲超时；chatOnce 对 503/429/502/504/529 重试 3 次
     · SSE 解析 → makeEmitter 30ms 合批 → chat:event
  → 渲染层 handleEvent 按 ctx 分流：
     普通 ctx：start/delta(帧合帧 rAF)/reasoning/done(mdHtml 终态)/error(补重试按钮)
     mergeMsg ctx：综合流式 → finalizeMergeCard（先作废 _paint 再落 Markdown）
     reviewCtx ctx：phase 2 互审条目 → all-done 后 phase 3 仲裁（部分停止则就地收尾）
  → all-done：pending.delete → 版本快照入池（10 版上限，裁剪折进 prunedTokens）
     → 自动综合/交叉审查触发（互斥：审查开启时综合让位）
  → 退出：win.close → app:flush → 渲染层 MM.save → window.close 放行（2.5s 超时强关兜底）
```

## 4. 数据流

- `MM.state{config, sessions}` ⇄ `store:save` → 主进程 `db` → `store.json`（tmp+rename 原子写；密钥 safeStorage/DPAPI 加密；多实例 mtime 冲突备份 .bak；解析失败备份 .corrupt-<ts>）。
- 图片：`userData/images/<hex>.<ext>`，store.json 只存引用；mmimg:// 协议白名单校验；孤儿 gc（损坏启动时跳过——本次修复）。
- 版本池：每轮 results 快照 10 版上限，inherited 标记防重综合重复记账，prunedTokens 承接裁剪用量。

## 5. 架构评估

**优点**：主/渲染职责切分清晰（密钥、网络、磁盘全在主进程）；chat:send 多目标复用一份管线承载回答/综合/互审三种流；merge.js 纯函数可测；测试分层（fast 零拉起 / electron 定向）设计良好。

**结构性弱点（进路线图）**：
1. ui-chat.js ~2850 行单文件承载全部聊天编排，改动半径大（本次 8 处修复集中于此）；
2. 全量整库保存（每轮 3~8 次 IPC，14MB 库实测 30ms/次 stringify）——无会话粒度增量；
3. 无 SQLite/分文件存储，store.json 随使用线性膨胀；
4. 渲染层 seq 计数、roundDomLru 等模块内可变状态缺少测试出口（本次已为部分补导出-friendly 的用例路径）。
